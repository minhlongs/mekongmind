# MEKONG wrapper — Claude Code CLI Integration Architecture Blueprint

## 1. Tổng quan hệ thống

MEKONG wrapper là solo company orchestrator kết hợp 3 lớp:
- **Mekong CLI** (business revenue orchestration): idea, market, offer, GTM, sales
- **ClaudeKit** (engineering verification factory): full-stack code, tests, review, deploy
- **CLAUDE.md/rules/** (harness DNA): goal-state, department-routing, SOP-gates

Target cuối cùng: first $1M MRR qua cloneable RaaS factory.

## 2. Claude Code CLI Integration Map

## 4. Department-to-CLAUDE.md Mapping

### engineering-factory (Claude Code Primary Role)
- **Input**: sops/departments/engineering-factory.md SOP + state gate evidence
- **Output**: source code, tests, build artifacts → state/evidence/
- **SOP Cells**: technical-design → mvp-build → integration → production-hardening
- **Gate Artifact**: `mvp-live.json` with fields: routes, apis, data_model, integrations, checkout_path, build_command, tests_run, known_risks

### quality-compliance  
- **Input**: sops/departments/quality-compliance.md SOP + code changes
- **Output**: structured audit report (security_issues, quality_violations, test_gaps, severity)
- **Gate Artifact**: `quality-audit.json` in state/evidence/

### platform-operations
- **Input**: sops/departments/platform-operations.md SOP + mvp build output  
- **Output**: deploy manifest, CI/CD configuration, infrastructure-as-code artifacts
- **Gate Artifact**: `platform-deploy.json` with environment configs and health check results

## 5. Claude Code Print Mode vs Interactive Mode Decision Matrix

| Task Type | Mode | CLI Command Example |
|---|---|---|
| Simple bug fix / typo | `-p` (Print) | `claude -p "Fix login validation" --max-turns 3` |
| New feature implementation | `-p` + tmux interactive | `claude -w feature-x --tmux` |  
| Code review / audit | `-p` (structured JSON output) | `claude -p "Review against quality-compliance SOP"` |
| Multi-step refactor | Interactive via tmux | `tmux send-keys 'Refactor auth module' Enter` |
| Build/test verification | `-p` (non-interactive) | `claude -p "Run build check and report issues" --max-turns 2` |

**Rule of thumb**: Use print mode (`-p`) whenever possible — cleaner, no dialog handling needed, structured output for evidence contracts. Switch to interactive tmux only when Claude needs back-and-forth conversation with you (not with other tools).

## 6. Performance Optimization for M1 Max 64GB

```bash
# Max parallel instances: 3 (matches settings.json max_parallel)
claude -p "Task A" --max-turns 10 &
claude -p "Task B" --max-turns 10 &  
claude -p "Task C" --max-turns 10 &
wait

# Model selection by complexity:
# Low effort: sonnet-4-6 (faster, cheaper)
# High effort: claude-opus-4-0-20250514 (deeper reasoning for complex logic)
claude -p "Complex multi-step refactor" --model claude-opus-4-0-20250514 --max-turns 15

# Context window health: /compact when >70% used
```

## 7. Anti-Chaos Rules (CRITICAL — never violate)

1. **No coding from raw idea** → always start with technical design first
2. **No mock-only success paths** → real integrations or explicit sandboxes ONLY  
3. **Evidence contracts must be deterministic** → same input structure = same output fields
4. **Don't bypass SOP gates** → if gate fails, escalate to CEO Command, don't force through

## 8. Pitfalls và cách tránh

| Pitfall | Impact | Solution |
|---|---|---|  
| Claude Code modifies state/ directly | Breaks MEKONG wrapper orchestration | Deny Write(state/*) in settings.json permissions |
| Parallel tasks > 3 on M1 Max | OOM when node_modules present | Enforce max_parallel=3 via settings |  
| Reusing context across sessions | Context window degradation >70% | Start fresh session for distinct tasks |
| Skipping build validation before handoff | Broken production artifacts | Make npm run build mandatory in skills |
| Using any types in TypeScript | Type safety lost, bugs propagate | Deny Read(state/*) in permissions + strict linting |

## 10. Quick Start Guide

### For MEKONG wrapper CLI (me command):
```bash
# Define the business goal  
me idea "Build RaaS clinic booking SaaS"

# Run department SOPs in sequence via mekong mind CLI
me solo run engineering-factory ready "MVP artifact ready"

# Check bottleneck and next steps
me solo bottlenecks --strict
```

### For Claude Code CLI:
```bash  
cd mvp   # Always work in this directory for code tasks

# Simple task (print mode) — recommended for automation
claude -p "Add error handling to login form" --allowedTools "Read,Edit,Bash" --max-turns 5

# Complex build (interactive via tmux)  
claude -w feature-x --tmux

# Pre-deploy checklist  
./bin/deploy.sh    # Triggers .claude/hooks/claude-deploy-prep.sh automatically
```

### Combined Workflow:
```bash
# Step 1: Define goal in MEKONG wrapper  
me idea "Build RaaS clinic booking SaaS"

# Step 2: Claude Code executes engineering tasks within mvp/  
cd mvp && claude -p "Implement booking flow" --allowedTools "Read,Write,Bash" --max-turns 10

# Step 3: Validate build passes
npm run build && npm test

# Step 4: Write evidence to state/ (via MEKONG wrapper CLI only, not Claude Code)  
me solo artifact validate engineering-factory state/evidence/mvp-live.json

# Repeat until gate passes → handoff to next department
```
